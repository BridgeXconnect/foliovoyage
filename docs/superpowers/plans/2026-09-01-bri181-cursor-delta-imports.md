# BRI-181: Cursor-Based Delta Imports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every import run (cron, external trigger, or manual CLI) resume from the previous run's true stopping point instead of always re-scanning Viator's entire ~800-page catalog, without touching cron enablement, deploy, or Linear.

**Architecture:** Add a new, never-nulled `ImportRun.lastCursor` column that tracks the last non-null pagination cursor a segment ever observed — distinct from the existing `cursor` column, which is deliberately nulled on a clean crawl finish as the signal that no more segments are needed. `ImportRunService.execute()` looks up the most recent non-`running` run that has a `lastCursor` and seeds the *new* run's existing `cursor` field with it at creation time. Every downstream consumer (`segment-worker.cli.ts`'s `startCursor`/`modifiedSince` gating, `ViatorClient.fetchModifiedSince`'s "never send both" guard) already exists and needs no changes — a cross-run resume becomes indistinguishable, at that layer, from a same-run segment resume.

**Tech Stack:** NestJS, Prisma (PostgreSQL), Jest, TypeScript — `apps/api`.

**Spec:** Linear BRI-181. No architecture-spec doc changes are in scope (this closes an implementation gap in the ST-10/BRI-107 ingest pipeline documented in `apps/api/CLAUDE.md`'s "Ingest pipeline" section — nothing in `docs/02` or `docs/03` needs updating for this fix).

## Global Constraints

- Do not enable or wire up `IMPORT_CRON_ENABLED` / cron scheduling as part of this work — the fix must work correctly for manual/triggered runs on its own. That is a separate future decision.
- Do not touch Linear — the reporting user closes BRI-181 themselves.
- Do not deploy. Land via a normal PR through CI only (`apps/api/CLAUDE.md`: "Do not deploy without explicit go-ahead from Roy").
- Follow existing test-fixture conventions exactly: in-memory fakes (`InMemoryImportRunStore`, `fakeSegmentRunner`, `fakeClient`/`fakeResumableClient`), not a mocking library.
- Every Prisma schema change needs a real migration generated via `prisma migrate dev` (not hand-authored SQL) and `prisma generate` re-run so the TypeScript types pick up the new column.
- Real Viator contract (verified live against `partnerresources.viator.com`, not memory): cursor-based walking is the only mechanism to use for a recurring resync; `modified-since` and `cursor` must never be sent in the same request; the correct resume value for a *new* cycle is the `nextCursor` from the *second-to-last* request of the prior cycle (i.e. the last non-null cursor seen before the terminating, cursor-less response) — never the terminating response itself.

```typescript
import type { ImportRunCounts } from "./import.pipeline";

/**
 * Increment expressions for one segment's counts, safe to apply repeatedly
 * (BRI-176) — pulled out of `segment-worker.cli.ts` into its own module so it
 * can be unit-tested without triggering that file's unconditional top-level
 * `void main()` bootstrap.
 *
 * `cursor` is always written, even `null` — that's how a segment signals
 * "the crawl reached its true end, no more segments needed" (see
 * `ImportPipeline.runSegment`). `lastPage` and `lastCursor` are guarded:
 * omitted entirely when this segment's own counts never set them, so an
 * update that only ran a segment with no progress on that front (e.g. its
 * only page was already the crawl's terminal page) doesn't clobber a value
 * an earlier segment already persisted on the row.
 */
export function incrementData(counts: ImportRunCounts) {
  return {
    fetched: { increment: counts.fetched },
    normalized: { increment: counts.normalized },
    quarantined: { increment: counts.quarantined },
    upserted: { increment: counts.upserted },
    cursor: counts.cursor,
    ...(counts.lastPage !== null ? { lastPage: counts.lastPage } : {}),
    ...(counts.lastCursor !== null ? { lastCursor: counts.lastCursor } : {}),
  };
}
```

```typescript
/** Minimal in-memory stand-in for Prisma's `importRun` model surface. */
class InMemoryImportRunStore implements ImportRunPrisma {
  readonly rows = new Map<string, ImportRun>();
  private seq = 0;

  importRun = {
    create: async ({ data }: { data: Record<string, unknown> }): Promise<ImportRun> => {
      this.seq += 1;
      const row = {
        id: `run-${this.seq}`,
        provider: (data.provider as string) ?? "viator",
        trigger: data.trigger as string,
        status: (data.status as ImportRun["status"]) ?? "running",
        fetched: 0,
        normalized: 0,
        quarantined: 0,
        upserted: 0,
        softDeleted: 0,
        cursor: (data.cursor as string | null | undefined) ?? null,
        lastPage: null,
        lastCursor: null,
        error: null,
        startedAt: new Date(),
        finishedAt: null,
      } as ImportRun;
      this.rows.set(row.id, row);
      return { ...row };
    },
    update: async ({
      where,
      data,
    }: {
      where: { id: string };
      data: Record<string, unknown>;
    }): Promise<ImportRun> => {
      const existing = this.rows.get(where.id);
      if (!existing) throw new Error(`no such run ${where.id}`);
      const updated = { ...existing, ...data } as ImportRun;
      this.rows.set(where.id, updated);
      return { ...updated };
    },
    updateMany: async ({
      where,
      data,
    }: {
      where: { status: ImportRun["status"]; startedAt: { lt: Date } };
      data: Record<string, unknown>;
    }): Promise<{ count: number }> => {
      let count = 0;
      for (const [id, row] of this.rows) {
        if (row.status === where.status && row.startedAt < where.startedAt.lt) {
          this.rows.set(id, { ...row, ...data } as ImportRun);
          count += 1;
        }
      }
      return { count };
    },
    findFirst: async ({
      where,
      orderBy,
    }: {
      where: {
        provider?: string;
        status?: ImportRun["status"] | { not: ImportRun["status"] };
        lastCursor?: { not: null };
      };
      orderBy?: { startedAt: "desc" | "asc" };
    }): Promise<ImportRun | null> => {
      const matches = (row: ImportRun): boolean => {
        if (where.provider !== undefined && row.provider !== where.provider) {
          return false;
        }
        if (where.status !== undefined) {
          if (typeof where.status === "string") {
            if (row.status !== where.status) return false;
          } else if (row.status === where.status.not) {
            return false;
          }
        }
        if (where.lastCursor?.not === null && row.lastCursor === null) {
          return false;
        }
        return true;
      };

      let candidates = [...this.rows.values()].filter(matches);
      if (orderBy?.startedAt === "desc") {
        candidates = candidates.sort(
          (a, b) => b.startedAt.getTime() - a.startedAt.getTime(),
        );
      } else if (orderBy?.startedAt === "asc") {
        candidates = candidates.sort(
          (a, b) => a.startedAt.getTime() - b.startedAt.getTime(),
        );
      }
      return candidates[0] ? { ...candidates[0] } : null;
    },
    findUniqueOrThrow: async ({
      where,
    }: {
      where: { id: string };
    }): Promise<ImportRun> => {
      const row = this.rows.get(where.id);
      if (!row) throw new Error(`no such run ${where.id}`);
      return { ...row };
    },
  } as unknown as ImportRunPrisma["importRun"];

  /** Test helper: insert a row directly, bypassing `create`'s auto-fields. */
  seed(row: Partial<ImportRun> & { id: string }): void {
    this.rows.set(row.id, {
      provider: "viator",
      trigger: "manual",
      status: "running",
      fetched: 0,
      normalized: 0,
      quarantined: 0,
      upserted: 0,
      softDeleted: 0,
      cursor: null,
      lastPage: null,
      lastCursor: null,
      error: null,
      startedAt: new Date(),
      finishedAt: null,
      ...row,
    } as ImportRun);
  }
}
```

In `apps/api/src/modules/import/import-run.service.ts`, add a new private method after `hasRunningRun()` (before the closing `private finalize` method, ~line 238):

```typescript
  /**
   * Look up the durable cross-run resume cursor (BRI-181): the most recent
   * *non-running* run for this provider that ever observed a `lastCursor`
   * value, regardless of that run's terminal status. Per Viator's own
   * ongoing-refresh contract (verified live against partnerresources.viator.com,
   * not memory), cursor-based walking is guaranteed not to miss any product
   * update regardless of exactly where a new cycle resumes from, and every
   * upsert in this pipeline is idempotent (see `TourUpsertService`) — so a
   * `failed` or `aborted` prior run is exactly as safe to resume from as a
   * `succeeded` one. Forcing a full re-crawl after any non-`succeeded` run
   * would burn bandwidth (the whole reason BRI-181 exists) for no
   * correctness benefit. A `running` row is excluded — its progress isn't a
   * settled resume point yet. Returns `null` (full crawl) when no row has
   * ever observed a `nextCursor` at all — this deployment's first run.
   */
  private async lookupResumeCursor(): Promise<string | null> {
    const previous = await this.prisma.importRun.findFirst({
      where: {
        provider: this.provider,
        status: { not: "running" },
        lastCursor: { not: null },
      },
      orderBy: { startedAt: "desc" },
    });
    return previous?.lastCursor ?? null;
  }
```

Modify `execute()` (~lines 167-174) to compute and seed the resume cursor:

```typescript
  async execute(
    trigger: ImportRunTrigger,
    options: ExecuteOptions = {},
  ): Promise<ImportRun> {
    // BRI-181: an explicit modifiedSince (the manual one-off re-sync escape
    // hatch) always wins over the auto-discovered cross-run cursor — asking
    // for a specific re-sync point means exactly that, not wherever the last
    // run happened to leave off.
    const resumeCursor = options.modifiedSince
      ? null
      : await this.lookupResumeCursor();

    const run = await this.prisma.importRun.create({
      data: {
        provider: this.provider,
        trigger,
        status: "running",
        cursor: resumeCursor,
      },
    });
    this.logger.log(
      resumeCursor
        ? `Import run ${run.id} started (trigger: ${trigger}), resuming from cursor "${resumeCursor}".`
        : `Import run ${run.id} started (trigger: ${trigger}), full crawl (no prior cursor).`,
    );
```
