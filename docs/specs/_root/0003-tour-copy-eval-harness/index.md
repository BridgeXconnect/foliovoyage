# 0003. Sampled evaluation and kill switch for AI tour copy

**Date**: 2026-09-25
**Status**: In Progress

## Summary

Spec 0002 blocks bad tour copy with a fast rule check before anything is stored, but rules cannot tell whether a sentence is actually true. This spec adds a judge (Claude Opus 5.5, a different model and a higher tier than the Sonnet 5 that writes the copy) that reads a sample of already published paragraphs next to their source fields and lists every claim as supported, unsupported, or contradicted. If more than 5% of a judged sample has a bad claim, every row from that prompt version and model is withdrawn automatically (hidden, not deleted). It also adds a 30 page human spot check, a frozen golden set that must be re run before any prompt or model change, and two gaps in the rule check (spelled out numbers, and voice counters that were never saved). Nothing here changes what visitors see today, because the web does not render `aiSummary` yet.

## Requirements

**User stories**:
- As Roy, I want bad tour copy to switch itself off when a sample shows a real problem so that I do not have to read paragraphs to keep the site honest.
- As Roy, I want to read 30 random paragraphs next to their source fields after a prompt or model change so that my own judgment calibrates the automated judge.
- As the engineer changing the prompt or the model, I want a fixed set of 60 real tours and 30 seeded paragraphs that fail the build when I skip them so that a change cannot ship untested.
- As the owner of the Viator relationship, I want copy that states facts the tour data does not contain to be found and pulled, because BRI-204 allows only the standard product fields.

**Acceptance criteria** (the contract, each criterion is IDed and independently checkable):
- **AC-1**: `TourCopyStatus` gains the value `withdrawn`. `TourCopy` gains `withdrawnAt`, `withdrawnByRunId`, `voiceCounts`, and `openingPattern` (all nullable). A `withdrawn` row keeps its `aiSummary`. `GET /v1/destinations/:country/:city` returns `aiSummary: null` for a tour whose row is `withdrawn`, with no other change to the response. A test covers it.
- **AC-2**: `TourCopyService.generateOne` skips a `withdrawn` row with the new skip reason `withdrawn_current` when its `promptVersion` equals `TOUR_COPY_PROMPT_VERSION` and its `model` equals the run's model, whatever its grounding hash is. A `withdrawn` row whose `promptVersion` or `model` differs is regenerated by the normal path, and the upsert returns it to `published` or `failed` and sets `withdrawnAt` and `withdrawnByRunId` back to null. No flag is needed for that. `tour-copy:run` also refuses to start, in both dry run and `--execute` (exit 1, a message naming the pair and the number of withdrawn rows), while any `withdrawn` row exists for its current pair (`TOUR_COPY_PROMPT_VERSION` plus the model that `checkTourCopyStartup` returns), so a withdrawn pair gets no new published rows either. Restoring the pair (AC-10), or changing the prompt version or the model, lifts the refusal. The refusal runs right after `checkTourCopyStartup` succeeds and before any model call. The candidate query and the dry run classifier in `tour-copy.cli.ts` (`classifyCandidate`, `iterateCandidates`) select `model` and apply the same `withdrawn_current` rule, so the dry run counts match a real run. The refusal looks only at the pair `tour-copy:run` is itself running, never at what an eval or withdraw run was narrowed to. If another pair is withdrawn, for example an older prompt version, `tour-copy:run` is not refused, and those withdrawn rows are regenerated at its own pair by the rule above.
- **AC-3**: The inline check blocks a paragraph that contains a spelled out number whose value is not present in the source fields (as digits or as the same word). It reuses the reason code `unsourced_number` and its corrective sentence is reworded to say "a number written as digits or as words". Checked words: `two` to `twenty`, `thirty` to `ninety` (and compounds such as `twenty five`), `hundred`, `thousand`, `million`, `dozen`. Not checked: `one` (a common pronoun and determiner) and ordinals such as `first` and `second`. Number reading rules, shared with AC-4: a hyphen counts as a space (`twenty-five`, `90-minute`), a compound has one value as a whole (`twenty five` is 25, `two hundred` is 200), and source digits are compared after removing commas (`1,200` is 1200). The system prompt states the rule, and `TOUR_COPY_PROMPT_VERSION` goes from 3 to 4. Unit tests cover compounds, a word that matches the source, a word that matches the source's digits, and the excluded words.
- **AC-4**: Every `published` row stores `voiceCounts` (`emDash`, `contrastiveReveal`, `clicheOrIntensifier`) and `openingPattern`, one of `duration` or `other`, computed by a pure function on the first sentence. `duration` means the first sentence contains a number or number word directly followed by `minute`, `minutes`, `hour`, `hours`, `day`, or `days`, read with the AC-3 number reading rules. The `tour-copy:run` summary prints totals of the three counters and the share of each opening pattern, and prints a warning line when the `duration` share of that run's published rows is above 40%.
- **AC-5**: A `TourCopyJudge` port with one Anthropic adapter judges one paragraph against its source fields. Every call goes to the same Cloudflare AI Gateway host as 0002 and nowhere else. The adapter sets `thinking` to disabled, forces a single tool `record_verdict` with `tool_choice`, sets `max_tokens` 1500 and a 90 second timeout, sets `cache_control` on the rubric system prompt as 0002's adapter does, sends no sampling parameters, wraps the source fields and the paragraph in delimited data blocks, and carries the five metadata entries with `content_type` set to `tour_copy_judge`. The judge model comes from optional `TOUR_COPY_JUDGE_MODEL` (default `claude-opus-5-5`) and must be on `TOUR_COPY_JUDGE_ALLOWED_MODELS`. It must also differ from the generator model of the run (`TOUR_COPY_MODEL`, default `claude-sonnet-5`), so the judge never grades its own model's work. Failing either check stops the eval and golden CLIs before database access, with a message that names both ids, and no model call is made. The run summary (AC-11) prints both model ids.
- **AC-6**: The judge result is validated in pure code. The tool input must have `claims` (a non empty list of `{text, verdict, evidence_quote}` with `verdict` one of `supported`, `unsupported`, `contradicted`), `leads_with_fact` (boolean), and `lead_fact` (string or null). A `supported` or `contradicted` claim whose `evidence_quote` is empty or not found in the source fields (compared after NFC normalization, lowercasing, and collapsing whitespace) is downgraded to `unsupported` and flagged `downgraded: true`. An `unsupported` claim may carry an empty `evidence_quote`. `claimVerdict` is `contradicted` if any claim is, else `unsupported` if any claim is, else `clean`. An invalid result, including a `max_tokens` stop reason, is retried once with the same input, and a second invalid result stores nothing and counts as `judge_invalid`. A `refusal` stop reason stores nothing and counts as `judge_refusal`.
- **AC-7**: `tour-copy-eval:run` judges only copy that is currently served: `published`, hash equal to a recomputed hash of the tour's current fields, tour not deleted, Experience published, and `evaluateTourCopyEligibility` still eligible. It never judges a row that already has a judge verdict for the same `copyGeneratedAt` and current rubric version. It also never judges a row whose stored `model` equals the judge model, because that would be the judge grading its own output. Because `model` is part of the pair key, a pair is either entirely `same_model` or has no such rows. A `same_model` pair is skipped whole, reported as `same_model` in the dry run and the run summary, and never withdrawn automatically, since it has no judge verdicts for the kill switch to count. Manual withdraw (AC-10) still works on it. For each `(promptVersion, model)` pair it judges (1) stage 1: the 50 served rows with the lowest `Tour.id`, whether or not they were judged before, of which only the unjudged ones are sent to the judge, then (2) a random top up so that every city has at least `min(60, served rows in that city)` judged rows for the pair, taking cities round robin in `City.id` order. A run judges at most `min(--limit, TOUR_COPY_EVAL_MAX_JUDGMENTS)` paragraphs (default cap 500), stage 1 of every pair first, then the top ups, with pairs ordered by `promptVersion` descending, then `model` ascending. Random choices use an injected seeded random source, so tests are deterministic. `--prompt-version` and `--model` narrow the pairs. The default is a dry run that makes no call and writes nothing, and prints counts per pair and city and an estimated input token total, computed as (rubric system prompt characters plus user message characters) divided by `CHARS_PER_TOKEN`. `--execute` runs it.
- **AC-8**: Each judged paragraph stores one `TourCopyEval` row (fields under Data model), unique on `(tourCopyId, copyGeneratedAt, evaluator, rubricVersion)`. A duplicate insert from a concurrent run is caught, counted as skipped, and does not fail the run. Human rows carry the current `tour_copy` rubric registry version in `rubricVersion`, so they fit the same unique key. Deleting a `TourCopy` deletes its `TourCopyEval` rows.
- **AC-9**: At the end of an `--execute` run, for each pair the kill switch counts the published rows that have a judge verdict for their current `generatedAt` and the current rubric version. If that count is at least 30 and more than 5% of those rows have `claimVerdict` other than `clean`, one `updateMany` sets `status = withdrawn`, `withdrawnAt`, and `withdrawnByRunId` on every `published` row of that pair, whether judged or not. The run prints the pair, the counts, and every bad page with its claim and evidence, and exits with code 2. Only the pairs the run was narrowed to by `--prompt-version` and `--model` are evaluated. Below 30 judged rows it makes no decision and prints the sample size. A dry run prints "would withdraw" and changes nothing. Rerunning after a withdrawal changes nothing, because the rows are no longer `published`.
- **AC-10**: `tour-copy-withdraw:run --prompt-version N --model M` withdraws a pair by hand, and with `--restore` returns its `withdrawn` rows to `published`. Both default to a dry run and need `--execute`. `--restore` refuses (exit 1, with the numbers) while the judged rows of that pair, counted over both `published` and `withdrawn` rows at the current rubric version, still cross the AC-9 limit (at least 30 judged rows and more than 5% bad). With fewer than 30 judged rows the restore proceeds. The message says to fix the prompt or bump the rubric version first. Bumping the rubric version discards every verdict for the pair, because AC-9 counts only the current version, so it lifts the refusal without new evidence. The control is that the stamp key changes (AC-16), so CI fails until the golden run is repeated. `--restore` sets `withdrawnAt` and `withdrawnByRunId` back to null. A manual withdraw writes a `randomUUID` generated by the CLI to `withdrawnByRunId`.
- **AC-11**: The eval run summary prints the run id, counts judged, skipped, `same_model` (rows the judge model itself generated, AC-7), `judge_invalid`, `judge_refusal`, and API errors, per pair the judged count and bad rate, the share of judged pages with `leadsWithFact` true, token totals including cache reads, the judge and generator model ids, and a warning line when that share is below 80%, when no human spot check exists for the pair, or when a pair's `duration` opening share is above 40%. Denominators: the `leadsWithFact` share is per pair, over the judge rows the kill switch counts (AC-9). "A human spot check exists" means at least `SPOTCHECK_SIZE` answered human rows (`g` or `b`, not skipped) for the pair at the current rubric version. The pair's `duration` share is over its published rows with a non null `openingPattern`. A low `leadsWithFact` share never withdraws anything.
- **AC-12**: The eval run stops at once on a 429 that survives the SDK's retries, printing the raw status and every `cf-aig-` response header, and stops after 5 consecutive API errors, where a timeout counts as an API error. Neither changes any existing row. Verdicts already stored in the run are kept, the kill switch is not evaluated, and the run exits 1. No more than `TOUR_COPY_EVAL_CONCURRENCY` (default 4) judge calls are in flight, and no row is judged twice in one run.
- **AC-13**: `tour-copy-spotcheck:run --prompt-version N --model M` (needs an interactive terminal) draws 30 published rows for the pair, taking randomly from rows that already have a judge verdict for their current copy and filling from unjudged rows only if fewer than 30 exist, and skipping rows that already have a human verdict. For each it prints the paragraph beside the five source fields and reads one key: `g` good, `b` bad (then `u` unsupported or `c` contradicted, and an optional note), or `s` skip. It also asks `y` or `n` for whether the paragraph leads with one specific, checkable fact. Each answer is saved at once as a `TourCopyEval` row with `evaluator = human` and the current `tour_copy` rubric version, so an interrupted session resumes. A `g` stores `claims: []` and `claimVerdict: clean`. A `b` stores one claim entry holding the note and the chosen verdict. An `s` stores nothing, so that row can be drawn again later. At the end it prints the human bad rate, agreement with the judge on rows that have both (agreement means both say clean, or both say bad, and exact verdict agreement is printed beside it), and every row where the judge said `clean` and the human said bad.
- **AC-14**: The golden set is committed under `apps/api/src/modules/content/golden/`: `tour-copy-golden-tours.json` (exactly 60 real tours, each with only the five source fields, an `id`, a `stratum` label, and a `referenceParagraph` that Roy reviewed as clean), and `tour-copy-golden-seeded.json` (exactly 30 paragraphs, each with a tour from the set, an expected `claimVerdict`, an expected `leadsWithFact`, and a one line `defect` description). The seeded set has 20 claim defects (10 unsupported, 6 contradicted, 4 subtle, such as an invented number word or a paraphrase that changes meaning) and 10 clean controls (4 of them grounded but not leading with a fact). A Jest test asserts counts, that every tour has exactly the five source fields and no price, rating, or cancellation field, and that every reference paragraph passes the inline check.
- **AC-15**: `tour-copy-golden:run` checks two things. **Part A (judge trust)** judges the 20 seeded claim defects and the 70 clean pages (60 reference paragraphs plus the 10 controls). It passes only if the judge flags at least 90% of the defects (18 of 20) and no more than 2% of the clean pages (1 of 70). It also prints agreement with the seeded `leadsWithFact` labels, report only. A judge call that ends as `judge_invalid` or `judge_refusal` fails the run (exit 1) and stops it at that call, and the run prints the failed call and the counts so far and reports no pass rates. **Part B (prompt under test)** runs only if Part A passed in the same `--part both` run. `--part a` and `--part b` are diagnostic runs that never write the stamp, and `--part b` runs alone with no Part A gate. Part B generates copy for the 60 tours with the current prompt and generator model, runs the inline check, judges every paragraph that passes it, and passes only if at least `EVAL_MIN_JUDGED` (30) paragraphs were judged and no more than 5% of those judged paragraphs have a bad claim. A judge call that ends as `judge_invalid` or `judge_refusal` fails Part B the same way. A generator refusal is not an API error and does not stop the run: it counts as a failed outcome in the inline check pass rate, like a check failure. The golden run makes its calls one at a time, never in parallel. Any API error, from the judge or the generator in either part, stops the run at that call with exit 1 and no further call is made, and a 429 that survives the SDK's retries also prints the raw status and every `cf-aig-` response header. The rule of 5 consecutive failures in AC-12 never applies to golden runs. Part B prints the inline check pass rate, the reason codes, the `leadsWithFact` share, and the `duration` opening share, report only. A dry run makes no call. `--part` defaults to `both`, and `--execute` runs whichever part was chosen. Only a `--part both` run in which both parts pass writes the stamp file `golden/tour-copy-golden-stamp.json` in the content module. It refuses to write the stamp unless the effective `TOUR_COPY_MODEL` and `TOUR_COPY_JUDGE_MODEL` equal `TOUR_COPY_MODEL_DEFAULT` and `TOUR_COPY_JUDGE_MODEL_DEFAULT`, and it records both effective models in the stamp. `--freeze-references` needs `--execute`, because it calls the generator, and writes `golden/tour-copy-golden-references.draft.json` for Roy to review and merge into the tours file by hand.
- **AC-16**: A Jest test fails when the stamp is missing, has `passed: false`, or has a `key` different from `sha256` of: `TOUR_COPY_SYSTEM_PROMPT`, the judge system prompt, the `record_verdict` tool schema, the rubric version, `TOUR_COPY_MODEL_DEFAULT`, `TOUR_COPY_JUDGE_MODEL_DEFAULT`, and the hash of the two golden data files, each hashed as canonical JSON (parsed, keys sorted) so a formatter or line endings do not change the key. So editing the prompt, changing either default model, changing the rubric or the tool schema, or editing the golden data fails CI until the golden run is repeated and its stamp committed. The stamp records the run id, date, both effective models, and both parts' numbers. The test needs no secrets and makes no model call.
- **AC-17**: Judge rubrics live in a registry keyed by content type, each entry holding a `version` and a `systemPrompt`. Only `tour_copy` is filled in. The judge port takes the content type and looks up its rubric. A test asserts that an unregistered content type throws.
- **AC-18**: The eval, spot check, withdraw, and golden code never call the generator (except golden Part B, which never writes to the database), never write `aiSummary`, and write only `TourCopyEval` rows and the `status`, `withdrawnAt`, and `withdrawnByRunId` fields of `TourCopy`.
- **AC-19**: `tour-copy-eval:run` and `tour-copy-golden:run` validate `AI_GATEWAY_BASE_URL`, `AI_GATEWAY_TOKEN`, and the judge and generator model ids at startup and exit non zero with a named message before touching the database. `tour-copy-withdraw:run`, `tour-copy-spotcheck:run`, and `tour-copy-golden:snapshot` make no model call, so they skip the gateway and model checks and need only the database, which keeps the manual withdraw usable during a gateway outage. Unit tests need no secrets, because model calls sit behind the two ports with fakes.

## Decision

**Chosen option**: Option 1: Judge a sample of already published copy in a separate command, store each verdict, and withdraw a whole prompt version and model pair when the sample crosses a limit.

The decisions inside that option, with the pick, the reason, and the runner up:

| Decision | Pick | Why | Runner up |
|---|---|---|---|
| Where the judge runs | A separate command over published rows, never inline before publishing | Layer 1 already blocks every paragraph. The judge is a quality sample, and inline judging would add a second call and latency to every tour. | Judge every paragraph before it is stored |
| Kill switch trigger | More than 5% of at least 30 judged pages have a bad claim | One number, measured on the judge's own verdicts | Two tiers (2% contradicted, 10% unsupported) |
| What is withdrawn | Every published row of the (prompt version, model) pair | Prompt failures are systematic, and Haiku and Sonnet behave differently at the same version | Prompt version alone, or one city |
| How it is withdrawn | New `withdrawn` status, reversible, text kept | Nothing is deleted, the read path already hides non `published` rows | Delete the copy, or a boolean flag |
| Regeneration | `tour-copy:run` refuses to start while its prompt version and model pair has withdrawn rows, and a withdrawn row is skipped at that pair whatever its hash. Changing the prompt version or the model regenerates automatically. | Stops the nightly job from rebuilding or adding copy at a pair the judge pulled, and lets a prompt fix land with no special flag | Skip only while the hash is unchanged (a changed tour would then republish bad copy at the same pair), or regenerate on any run |
| Judge model | `claude-opus-5-5` through the same gateway, forced tool output, thinking disabled. Final decision | Maximal independence: a different model and a higher tier than the Sonnet 5 generator, and the safest available choice against missing subtle claims. Comparing a claim with its source does not need Opus's full capability, but nothing about the task makes it a poor fit either. It has no prior proof on this gateway, unlike Sonnet 5 and Haiku 4.5, so build task 13 is its first real confirmation. Not a cost tier choice | Haiku 4.5 (independent, smaller, already proven on this gateway), or Sonnet 5 (the generator's own model, no independence) |
| Judge output | A list of claims, each supported, unsupported, or contradicted, with a quote from the source | A quote can be checked in code, so a made up "supported" is downgraded | A single pass or fail score |
| Verdict storage | New `TourCopyEval` table shared by judge and human rows | Judge and human agreement becomes a query, and the text judged survives regeneration | Columns on `TourCopy` |
| Voice rubric 2b | Judged and counted, report only, never withdraws | Weak style is not unsafe copy, the same reasoning as 0002's non blocking voice counters | Withdraw on a low share |
| Sampling | 100% of the first 50 rows of a pair, then a random floor of 60 per city, capped at 500 per run | Early volume is where a new prompt shows its failure, and the floor keeps every city covered | A fixed percentage |
| Human spot check | 30 random pages per new prompt version or model, interactive, recorded as `human` rows | Judge calibration needs a human signal, and 30 fits one sitting | A JSON file round trip |
| Golden set | 60 real tour snapshots with reviewed reference paragraphs, plus 30 seeded paragraphs, committed as JSON | Reproducible in every worktree and CI, and the repo is private | R2 or local files |
| Judge trust bar | At least 90% of planted defects caught, at most 2% of clean pages flagged | A judge that flags 5% of good pages would trip a 5% kill switch by chance about half the time (see rationale) | 5% false positives |
| Golden gate | A committed stamp keyed by a hash of the prompt, models, rubric, and golden data, checked by Jest | Makes "run the golden set first" a CI failure instead of a habit | promptfoo, or a manual habit |
| Tour copy vs BRI-152 | Tour copy first, with a rubric registry keyed by content type | BRI-152's curation rule needs its own rubric, which cannot be written well before tour copy is judged | Design both rubrics now |
| Layer 1 gaps | Spelled out numbers block under `unsourced_number`. Voice counters and an opening pattern are stored per row. | Both were left to this spec by 0002 | Leave them |
| Notification | Stdout and exit code 2 on withdrawal | The eval is manual today, and the future cron surfaces a non zero exit | A message integration |
| Spend control | A per run judgment cap plus the gateway rules of 0002. No local dollar ledger. | Same reasoning as 0002. The BRI-206 file guard belongs to DataForSEO calls, not model calls. | A local spend guard |

## Feature design

**Data model sketch**:

`TourCopy` (existing, changed):

| Field | Type | Change |
|---|---|---|
| `status` | enum `TourCopyStatus` | adds `withdrawn` |
| `withdrawnAt` | timestamp, nullable | new, set to null when the row is regenerated or restored |
| `withdrawnByRunId` | text, nullable | new, set to null when the row is regenerated or restored |
| `voiceCounts` | JSON, nullable | new: `{emDash, contrastiveReveal, clicheOrIntensifier}` |
| `openingPattern` | text, nullable | new: `duration` or `other` |

`TourCopyEval` (new, one row per judgment):

| Field | Type | Notes |
|---|---|---|
| `id` | PK | |
| `tourCopyId` | FK to `TourCopy`, many to one, cascade delete | |
| `copyGeneratedAt` | timestamp | The `generatedAt` of the copy judged, so a verdict stays tied to the exact text |
| `judgedText` | text | The paragraph judged |
| `promptVersion`, `model`, `groundingHash` | int, text, text | Copied from the row when judged |
| `evaluator` | enum `TourCopyEvaluator`: `judge`, `human` | |
| `evaluatorModel` | text, nullable | `claude-opus-5-5` for the judge, null for a human |
| `rubricVersion` | int | Bumped whenever the rubric text changes. Human rows carry the current registry version for `tour_copy`. |
| `claims` | JSON | List of `{text, verdict, evidenceQuote, downgraded?}`. A human `b` verdict stores one entry holding the note, and a human `g` stores an empty list. |
| `claimVerdict` | enum `TourCopyClaimVerdict`: `clean`, `unsupported`, `contradicted` | Worst claim on the page |
| `leadsWithFact` | boolean | Rubric 2b |
| `evalRunId` | text | Groups one CLI run |
| `createdAt` | timestamp | |

Unique on `(tourCopyId, copyGeneratedAt, evaluator, rubricVersion)`. Indexed on `(promptVersion, model)`. One migration creates the enum value, the columns, the two enums, and the table.

**State transitions**:
- `TourCopy.status`: `published` to `withdrawn` (kill switch or manual withdraw). `withdrawn` to `published` (`--restore`). `withdrawn` to `published` or `failed` (regeneration after the prompt version or model changed, per AC-2). `published` and `failed` behave as in 0002.
- Only `tour-copy-eval:run` and `tour-copy-withdraw:run` move a row to `withdrawn`. Only `tour-copy-withdraw:run --restore` and `tour-copy:run` move it back. `tour-copy:run` refuses to run at a pair that has withdrawn rows (AC-2).

**Command surface** (no HTTP endpoint is added):

| Command (package script) | Flags | Writes | Exit codes |
|---|---|---|---|
| `tour-copy-eval:run` | `--execute`, `--limit N`, `--prompt-version N`, `--model M` | `TourCopyEval` rows, and `withdrawn` status on a limit crossing | 0 ok, 1 startup or abort error, 2 withdrawal happened |
| `tour-copy-spotcheck:run` | `--prompt-version N`, `--model M`, `--count N` (default 30) | human `TourCopyEval` rows | 0 ok, 1 not a terminal |
| `tour-copy-withdraw:run` | `--prompt-version N --model M`, `--restore`, `--execute` | `status`, `withdrawnAt`, `withdrawnByRunId` | 0 ok, 1 refused |
| `tour-copy-golden:run` | `--execute`, `--part a|b|both` (default `both`), `--freeze-references` (needs `--execute`) | the stamp file (only for `--part both`), or `golden/tour-copy-golden-references.draft.json` with `--freeze-references` | 0 pass, 1 fail or refused |
| `tour-copy-golden:snapshot` | `--execute` | `tour-copy-golden-tours.json` (without reference paragraphs), and it refuses to overwrite an existing file | 0 ok, 1 refused |
| `tour-copy:run` (existing, changed) | as in 0002 | as in 0002, plus `voiceCounts` and `openingPattern` | as in 0002, plus 1 when its pair has withdrawn rows |

All run through `doppler run --` like the existing CLIs. The read endpoint changes only by AC-1.

| Action | Value produced / displayed | Source |

| Choose rows to judge | already judged | existing `TourCopyEval` for `(tourCopyId, copyGeneratedAt, judge, current rubric version)` |
| Choose rows to judge | the two sampling numbers 50 and 60, and the run cap | code constants, and `TOUR_COPY_EVAL_MAX_JUDGMENTS` |
| Choose rows to judge | random choices | an injected seeded random source (fixed seed in tests, a fresh seed per run otherwise) |
| Dry run | estimated input tokens | (rubric system prompt characters plus user message characters) divided by `CHARS_PER_TOKEN` in `tour-copy.constants.ts`, input only |
| Judge one paragraph | source fields | the tour's current five grounding fields, through the same serializer as 0002 |
| Judge one paragraph | rubric text and version | the rubric registry, keyed by content type `tour_copy` |
| Judge one paragraph | model | `TOUR_COPY_JUDGE_MODEL`, default `claude-opus-5-5`, checked against `TOUR_COPY_JUDGE_ALLOWED_MODELS` and against the run's generator model |

| Kill switch | who withdrew | `withdrawnByRunId` = the eval run id |
| Spot check | which 30 pages | random rows of the pair, preferring rows with a judge verdict |
| Spot check | verdict, note, lead | keystrokes at the terminal |
| Spot check | `rubricVersion` of a human row | the current `tour_copy` registry version |
| Manual withdraw | `withdrawnByRunId` | a `randomUUID` generated by the CLI |
| Opening pattern | `duration` or `other` | pure function on the first sentence of the stored paragraph |
| Golden | the 60 tours | committed JSON, produced once by `tour-copy-golden:snapshot` from `Tour` rows chosen by strata |
| Golden | stamp key | sha256 of the prompt text, the judge prompt, the `record_verdict` schema, both default models (`TOUR_COPY_MODEL_DEFAULT`, `TOUR_COPY_JUDGE_MODEL_DEFAULT`), rubric version, and the golden data files as canonical JSON |
| Golden | stamp models | the effective `TOUR_COPY_MODEL` and `TOUR_COPY_JUDGE_MODEL` of the run, which must equal the defaults for the stamp to be written |
| Golden | Part A and Part B bars | code constants `GOLDEN_RECALL_MIN` (0.9), `GOLDEN_CLEAN_FLAG_MAX` (0.02), `EVAL_MAX_BAD_RATE` (0.05), and `EVAL_MIN_JUDGED` (30) as the Part B minimum |

**Key invariants**:
- A `withdrawn` row is never served, and `aiSummary` is never cleared by this feature. `tour-copy:run` writes no new published row at a pair that has withdrawn rows.
- Judge output never causes a side effect beyond one stored row. The judge has one tool, whose result is only validated and stored.
- The judge model is always on the allowlist, never equals the generator model of the run, is never used on a row whose stored `model` is the same model, and is stored on every verdict (`evaluatorModel`).
- A verdict is only ever counted against the exact copy it judged (`copyGeneratedAt`) and the rubric version it used.
- The kill switch acts only on judge rows. Human rows and the voice rubric never withdraw anything.
- Every judge call goes through the gateway, carries the five metadata entries, and Atlas stores no dollar amount.
- The golden run writes nothing to the database.

**Security model**: no new HTTP surface and no new roles. The commands run locally under Doppler and, later, on Railway. Provider text is untrusted, so it reaches the judge only inside delimited data blocks, and the judge has no tool that acts on it. Gateway payload logging stays on as in 0002, so the judge prompts (provider text plus generated copy) are visible in Cloudflare. No personal data is involved. Committed golden data holds standard Viator product fields only, in a private repository.

**Configuration required**:
- `TOUR_COPY_JUDGE_MODEL`: optional, default `claude-opus-5-5`, must be on `TOUR_COPY_JUDGE_ALLOWED_MODELS` and must differ from the run's generator model.
- `TOUR_COPY_EVAL_MAX_JUDGMENTS`: optional, default 500, ceiling on judgments per run.
- `TOUR_COPY_EVAL_CONCURRENCY`: optional, default 4.
- Code constants in `tour-copy-eval.constants.ts`: `EVAL_MIN_JUDGED` 30, `EVAL_MAX_BAD_RATE` 0.05, `EVAL_FIRST_ROWS_FULL` 50, `EVAL_CITY_FLOOR` 60, `SPOTCHECK_SIZE` 30, `GOLDEN_RECALL_MIN` 0.9, `GOLDEN_CLEAN_FLAG_MAX` 0.02, `DURATION_OPENING_WARN_SHARE` 0.4, `LEADS_WITH_FACT_WARN_FLOOR` 0.8, the judge `max_tokens` 1500 and timeout 90 seconds, `TOUR_COPY_JUDGE_MODEL_DEFAULT` (`claude-opus-5-5`, the constant behind the env default), and `TOUR_COPY_JUDGE_ALLOWED_MODELS` (only `claude-opus-5-5` to start, and widening it is a reviewed code change). All are starting values, tuned during calibration.
- Cloudflare: no new resource. The 0002 monthly spend rule is shared, so judge spend counts against it. Judge calls run on Opus 5.5, which has never been called through this gateway (Sonnet 5 and Haiku 4.5 were both confirmed in BRI-154 calibration, Opus was not). Build task 13 is its first real confirmation: the model string is accepted, the BYOK routing works, and the judge calls, which carry `content_type` `tour_copy_judge`, show up in the gateway log with a nonzero cost.
- Files: `apps/api/.env.example` lists the three new variables. `apps/api/package.json` gains the five scripts. Doppler `dev` and `prd` gain nothing required (all three variables have defaults).

**Critical test scenarios** (each maps to an acceptance criterion in ## Requirements):
- Happy path: fake judge marks 40 published rows clean, the run stores 40 `TourCopyEval` rows, makes no withdrawal, and exits 0, verifies **AC-7**, **AC-8**, **AC-9**
- Kill switch: fake judge marks 3 of 40 rows `unsupported`, all published rows of that pair become `withdrawn`, other pairs are untouched, exit code 2, verifies **AC-9**
- Small sample: 20 judged rows with 5 bad makes no decision and prints the sample size, verifies **AC-9**
- Read path: a withdrawn row returns `aiSummary: null` from the destination endpoint, verifies **AC-1**
- Regeneration: a withdrawn row at the current version is skipped as `withdrawn_current` even after its tour changed (hash differs), `tour-copy:run` refuses to start at that pair (exit 1, message names the pair), and after the prompt version bump the row is regenerated with `withdrawnAt` and `withdrawnByRunId` back to null, verifies **AC-2**
- Downgrade: a `supported` claim with a quote that is not in the source is stored as `unsupported` with `downgraded: true`, verifies **AC-6**
- Failure case: a 429 stops the run, prints the `cf-aig-` headers, and leaves rows unchanged, verifies **AC-12**
- Duplicate: two runs judging the same row store one verdict and the second run counts a skip, verifies **AC-8**
- Other pair not refused: with one pair withdrawn, `tour-copy:run` at a different prompt version or model starts, and regenerates the withdrawn rows at its own pair, verifies **AC-2**
- Restore refusal: `--restore` on a pair whose judged rows still cross the limit exits 1, verifies **AC-10**
- Stale copy: a row whose tour changed after generation (hash mismatch) is never judged, verifies **AC-7**
- Stamp gate: changing one character of the system prompt makes the stamp test fail, verifies **AC-16**
- Judge equals generator model: the pure startup check, given the same model id for both (a unit test passes it directly, since 0002's allowlist would reject Opus as a generator first), refuses and the message names both ids, and the CLI exits non zero before touching the database and makes no model call, verifies **AC-5**
- Row generated by the judge model: a pair whose stored `model` equals the judge model is not judged, is counted as a `same_model` skip in the dry run and the summary, is never withdrawn by the eval run, and can still be withdrawn by hand, verifies **AC-7**, **AC-10**, **AC-11**
- Narrowed run: with `--model M` only the pairs of model M are judged and evaluated by the kill switch, verifies **AC-7**, **AC-9**
- Aborted run: after 5 consecutive API errors the stored verdicts remain, no withdrawal happens, and the exit code is 1, verifies **AC-12**
- Human rows: a `g` answer stores a clean row with no claims and the current rubric version, an `s` answer stores nothing, verifies **AC-8**, **AC-13**
- Restore: `--restore` returns rows to `published` with `withdrawnAt` and `withdrawnByRunId` null, verifies **AC-10**
- Golden Part A failure: one `judge_invalid` result in Part A fails the run and Part B does not run, verifies **AC-15**
- Golden part flags: `--part b` alone runs Part B with no Part A gate, and neither `--part a` nor `--part b` writes the stamp, verifies **AC-15**
- Golden stop at first failure: the golden run is sequential, and after a failed judge call or any API error it makes no further calls, and a 429 also prints the raw status and the `cf-aig-` headers, verifies **AC-15**
- Golden generator refusal: a generator refusal in Part B does not stop the run and counts as a failed outcome in the inline check pass rate, verifies **AC-15**
- Golden Part B floor: fewer than 30 judged paragraphs fails Part B even with no bad claim, verifies **AC-15**
- Stamp refusal: `--execute` with a non default effective model does not write the stamp, verifies **AC-15**

## Consequences

**Positive**:
- Untrue claims that pass the rule check are found by a second model with a checkable quote, and a bad prompt version is pulled from the site by itself.
- Bad copy falls back to the provider text, which 0002 already serves, so withdrawing costs no page anything.
- The stamp turns "run the golden set" into a CI failure, so a prompt or model change cannot merge untested.
- Judge and human verdicts share a table, so agreement is a query and the judge can be corrected against real reading.
- Voice drift (duration led openings) becomes a number per run instead of something noticed by accident.

**Negative / tradeoffs**:
- The check is after the fact. A bad page stays live until the next eval run, and a single bad page below the limit stays live, listed in the run report but not withdrawn. Today no page is exposed, because the web does not render `aiSummary`.
- The judge is a model and can be wrong. The 2% clean flag bar on the golden set limits false alarms but does not remove them. At the smallest decision sample (30 pages, so 2 bad pages trips the limit) a judge that truly flags 1% of good pages still withdraws a perfect pair about 4% of the time. `--restore` exists for that, and it is refused while the numbers still cross.
- The judge shares the monthly gateway spend rule with generation, so heavy judging can use up the budget generation needs. The run cap bounds the judge's share.
- The judge model has no prior proof on this gateway. Sonnet 5 and Haiku 4.5 were both confirmed during BRI-154 calibration and Opus 5.5 was not, so its model string, routing, gateway cost and forced tool behavior are all unconfirmed until build task 13. That task is its first real confirmation, and nothing else in calibration should be trusted before it passes.
- Independence does not make Part A a full measure of the judge. Its 20 planted defects (4 of them subtle) were written by people, not by the generator, so a 90% recall there does not prove the judge catches the generator's own natural mistakes. The quote check in code (AC-6), which does not depend on the model, and the human spot check (AC-13), whose agreement report is the real evidence, are the controls.
- The golden stamp is self reported by whoever ran the command, and CI can only check that it matches, not that the run was honest. A reviewer reading the stamp diff is the control.
- Committed golden data is provider text in git history. It is standard product fields in a private repository, and would need a rethink if the repository ever became public.
- Failed generations still store no text, so the "81 real failures" cannot be replayed. The golden set uses the tours, not the wording.
- A spelled out number check cannot cover `one` or ordinals, so "one guide" invented from nothing passes Layer 1. The judge is the backstop.
- Withdrawal is keyed by prompt version and model. A change that touches neither (a check change) does not withdraw or regenerate existing rows, only the judge sample notices.
- The refusal in `tour-copy:run` (AC-2) depends on withdrawn rows existing. Once every withdrawn row of a pair has been regenerated under another prompt version or model, going back to the old pair is not blocked. A small table holding pair state would close that, and is left as a follow up.
- Once the nightly cron is wired (scope row 10), the nightly `tour-copy:run` will exit 1 every night while a pair is withdrawn (AC-2), until someone restores the pair, bumps the prompt version or changes the model. That is intended, and it will show as a failed job.
- Bumping the rubric version discards a pair's verdicts and so lets `--restore` through without new evidence (AC-10). The stamp key changes, so CI fails until the golden run is repeated, and that is the only control.
- Adding an enum value and a table is a schema change on a Neon production database, and needs Roy's go ahead before any deploy.

**Neutral**:
- Existing published rows created before this spec have null `voiceCounts` and `openingPattern` until regenerated.
- The rubric registry is ready for BRI-152, but `TourCopyEval` is tour copy specific. BRI-152 will add its own table or generalize this one.
- Nightly evaluation is not wired. The commands are manual, and the Railway cron is a separate approved step.
